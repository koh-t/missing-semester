## エイリアスと関数

想像がつくとおり、たくさんのフラグや冗長なオプションを伴う長いコマンドを入力するのは、うんざりしてくるものです。とはいえ、ほとんどのシェルは**エイリアス**をサポートしています。たとえば、bashのエイリアスは次のような構造をしています(`=` 記号の前後にスペースがないことに注意してください)。

```bash
alias alias_name="command_to_alias"
```

<!-- `alias ll=ls -ltAh` のように、コマンドでよく使うフラグにエイリアスを付けることができます。エイリアスは組み合わせることもできます  -->

エイリアスには便利な機能がたくさんあります

```bash
# Alias can summarize good default flags
alias ll="ls -lh"

# Save a lot of typing for common commands
alias gc="git commit"

# Alias can overwrite existing commands
alias mv="mv -i"
alias mkdir="mkdir -p"

# Alias can be composed
alias la="ls -A"
alias lla="la -l"

# To ignore an alias run it prepended with \
\ls
# Or can be disabled using unalias
unalias la

```
<!--
エイリアスを取り除くには `unalias alias_name` を実行します。コマンドの実行時にエイリアスを無視するには、コマンドの前にバックスラッシュを付けて `\alias_name` とします。これは、エイリアスが既存の名前を上書きしている場合に便利です。 -->


しかし、多くの場面でエイリアスには限界があります。特に、同じ引数を取るコマンドを連結して書こうとする場合です。その代わりになるのが**関数**で、これはエイリアスと自作のシェルスクリプトの中間に位置するものです。

以下は、ディレクトリを作成してその中に移動する関数の例です。

```bash
mcd () {
    mkdir -p $1
    cd $1
}
```

エイリアスと関数は、デフォルトではシェルのセッションをまたいで保持されません。エイリアスを永続化するには、`.bashrc` や `.zshrc` のようなシェルの起動スクリプトファイルのいずれかに書いておく必要があります。私のおすすめは、エイリアスを `.alias` に別途まとめておき、各シェルの設定ファイルからそのファイルを `source` することです。

<!-- 最後に、これらのツールのいずれかに「改良版」でエイリアスを付けることにした場合(たとえば `alias bat=cat`)、`\cat` とすればエイリアスを無視するよう、`command cat` とすればエイリアスと関数の両方を無視するようbashに指示できることを知っておくと便利です -->

## シェルとフレームワーク

シェルとスクリプトの講義では `bash` シェルを扱いました。これは群を抜いて広く普及しているシェルで、ほとんどのシステムでデフォルトの選択肢になっているからです。とはいえ、選択肢はそれだけではありません。

たとえば `zsh` シェルは `bash` のスーパーセットで、次のような便利な機能を最初から数多く備えています。

- より賢いグロブ、`**`
- インラインでのグロブ/ワイルドカード展開
- スペル修正
- より優れたタブ補完/選択
- パス展開(`cd /u/lo/b` が `/usr/local/bin` に展開されます)

さらに、多くのシェルは**フレームワーク**で改善できます。人気のある汎用フレームワークには[prezto](https://github.com/sorin-ionescu/prezto)や[oh-my-zsh](https://github.com/robbyrussell/oh-my-zsh)があり、特定の機能に特化した小さなものには、たとえば[zsh-syntax-highlighting](https://github.com/zsh-users/zsh-syntax-highlighting)や[zsh-history-substring-search](https://github.com/zsh-users/zsh-history-substring-search)があります。[fish](https://fishshell.com/)のような他のシェルは、こうしたユーザーフレンドリーな機能の多くをデフォルトで備えています。そうした機能には次のようなものがあります。

- 右プロンプト
- コマンドのシンタックスハイライト
- 履歴の部分文字列検索
- manページに基づくフラグの補完
- より賢い自動補完
- プロンプトのテーマ

これらのフレームワークを使う際にひとつ注意すべきなのは、フレームワークが実行するコードが適切に最適化されていなかったり、コードの量が多すぎたりすると、シェルが遅くなり始めることがある点です。いつでもプロファイリングして、あまり使わない機能や、速度ほどには重視していない機能を無効化できます。

## ターミナルエミュレータとマルチプレクサ

シェルのカスタマイズとあわせて、どの**ターミナルエミュレータ**を選び、どう設定するかを検討するのに時間を割く価値があります。世の中にはたくさんのターミナルエミュレータがあります([比較](https://anarc.at/blog/2018-04-12-terminal-emulators-1/)はこちら)。

ターミナルの中で数百時間から数千時間を過ごすことになるかもしれないので、その設定を調べておくことは十分に報われます。ターミナルで変更したくなるであろう点には、次のようなものがあります。

- フォントの選択
- カラースキーム
- キーボードショートカット
- タブ/ペインのサポート
- スクロールバックの設定
- パフォーマンス([Alacritty](https://github.com/jwilm/alacritty)のような比較的新しいターミナルは、GPUアクセラレーションを提供しています)

[tmux](https://github.com/tmux/tmux)のような**ターミナルマルチプレクサ**にも触れておく価値があります。`tmux` を使うと、複数のシェルセッションをペインやタブに分けて扱えます。アタッチとデタッチもサポートしています。これは、リモートサーバーで作業していて、現在のプロセスをdisownすることを気にせずにシェルを動かし続けたいときの、非常によくあるユースケースです(デフォルトでは、ログアウトするとプロセスは終了させられます)。このように、`tmux` があれば複雑なターミナルのレイアウトに出入りできます。ターミナルエミュレータと同様に、`tmux` も `~/.tmux.conf` ファイルを編集することで大幅なカスタマイズができます。


## コマンドラインユーティリティ

ほとんどのUNIX系オペレーティングシステムにデフォルトで備わっているコマンドラインユーティリティは、普段やる必要のあることの99%をこなすのに十分すぎるほどです。


以降のいくつかの小節では、きわめてよく行うシェル操作について、より便利に使える代替ツールを紹介します。これらのツールの中には、コマンドに改良された新しい機能を追加するものもあれば、より良いデフォルトを備えた、よりシンプルで直感的なインターフェースを提供することだけに注力しているものもあります。

### `fasd` vs `cd`

パス展開やタブ補完が改善されていても、ディレクトリの移動はかなりの繰り返し作業になることがあります。[Fasd](https://github.com/clvv/fasd)(または[autojump](https://github.com/wting/autojump))は、最近訪れたフォルダやよく訪れるフォルダを記録し、あいまいマッチングを行うことで、この問題を解決します。

そのため、`/home/user/awesome_project/code` というパスを訪れたことがあれば、`z code` を実行するとそこに `cd` します。codeという名前のフォルダが複数ある場合は、`z awe code` を実行すれば、より近くマッチするほうに絞り込めます。autojumpと違って、fasdは、`cd` を行う代わりに、よく使う/最近使ったファイルやフォルダ、またはその両方を展開するだけのコマンドも提供しています。


### `bat` vs `cat`

`cat` はその役目を完璧に果たしますが、[bat](https://github.com/sharkdp/bat)は、シンタックスハイライト、ページング、行番号、gitとの統合を提供することでそれを改良しています。


### `exa`/`ranger` vs `ls`

`ls` は優れたコマンドですが、サイズを生のバイト数で表示するなど、デフォルトの中には煩わしいものもあります。[exa](https://github.com/ogham/exa)はより良いデフォルトを提供します

多くのフォルダを行き来したり、多くのファイルをプレビューしたりする必要があるなら、[ranger](https://github.com/ranger/ranger)は、そのすばらしいインターフェースのおかげで `cd` や `cat` よりもはるかに効率的になりえます。かなりカスタマイズが利き、正しく設定すればターミナルで[画像をプレビュー](https://github.com/ranger/ranger/wiki/Image-Previews)することさえできます

### `fd` vs `find`

[fd](https://github.com/sharkdp/fd)は、`find` に代わるシンプルで高速、かつユーザーフレンドリーなツールです。`find` では `--name` フラグを使わなければならない(99%の場合、やりたいのはこれです)といった点がデフォルトで改められており、日常的に使いやすくなっています。また、`git` を認識し、デフォルトで `.gitignore` に書かれたファイルと `.git` フォルダをスキップします。デフォルトで見やすい色分けもされます。

### `rg/fzf` vs `grep`

`grep` は優れたツールですが、多くのファイルを一度にgrepしたいなら、その目的にもっと適したツールがあります。[ack](https://github.com/beyondgrep/ack3)、[ag](https://github.com/ggreer/the_silver_searcher)、[rg](https://github.com/BurntSushi/ripgrep)は、gitignoreのルールを尊重しながら、カレントディレクトリを正規表現パターンで再帰的に検索します。どれもほぼ同じように動作しますが、私はホームディレクトリ全体を非常に高速に検索できることから `rg` を好んで使っています。

同様に、気づけば `CMD | grep PATTERN` を何度も何度も繰り返している、ということもよくあります。[fzf](https://github.com/junegunn/fzf)はコマンドラインのファジーファインダーで、ほぼどんなコマンドの出力でも対話的に絞り込めるようにしてくれます。

### `rsync` vs `cp/scp`

`mv` や `scp` はほとんどの場面で申し分ありませんが、大量のファイルや大きなファイルをコピー/移動するとき、あるいはデータの一部がすでにコピー先にあるときには、`rsync` を使うと大幅に改善されます。`rsync` はすでに転送済みのファイルをスキップし、`--partial` フラグを使えば、以前に中断されたコピーを途中から再開できます。

### `trash` vs `rm`

`rm` は、一度ファイルを削除したら取り返しがつかないという意味で、危険なコマンドです。しかし、最近のOSは、ファイルエクスプローラで何かを削除したときにそのようには振る舞いません。定期的に空にされるゴミ箱フォルダに移動するだけです。

ゴミ箱の管理方法はOSによって異なるため、単一のCLIユーティリティはありません。macOSには[trash](https://hasseg.org/trash/)があり、Linuxには[trash-cli](https://github.com/andreafrancia/trash-cli/)などがあります。

### `mosh` vs `ssh`

`ssh ` はとても便利なツールですが、接続が遅いとラグが煩わしくなることがあり、接続が途切れると再接続しなければなりません。[mosh](https://mosh.org/)は、ローミングを可能にし、断続的な接続をサポートし、賢いローカルエコーを提供してくれる便利なツールです。

### `tldr` vs `man`

コマンドが何をするのか、どんなオプションがあるのかは、たいていの場合 `man` や `-h`/'--help' フラグを使って調べられます。しかし、内容が詳細な場合には、それらを読み進めるのに少し気後れすることもあります

[tldr](https://github.com/tldr-pages/tldr)コマンドは、コミュニティ主導のドキュメントシステムで、コマンドラインから利用できます。そのコマンドが何をするのかを示すシンプルでわかりやすい例をいくつかと、もっともよく使われる引数オプションを教えてくれます。


### `aunpack` vs `tar/unzip/unrar`

[このxkcd](https://xkcd.com/1168/)が触れているように、`tar` のオプションを覚えるのはなかなか厄介ですし、.rarファイルには `unrar` というように、まったく別のツールが必要になることもあります。
[atool](https://www.nongnu.org/atool/)パッケージが提供する `aunpack` コマンドは、正しいオプションを自動で判断し、展開したアーカイブを常に新しいフォルダに置いてくれます。

1. ターミナルエミュレータをひとつ選び、次のプロパティを変更する方法を調べてください。
    - フォントの選択
    - カラースキーム。標準的なスキームには何色あるでしょうか?それはなぜでしょうか?
    - スクロールバック履歴のサイズ

1. `fasd` または類似のソフトウェアをインストールし、渡された引数に対してあいまいマッチングを行い、最上位の結果をお好みのエディタで開く `v` というbash/zsh関数を書いてください。次に、マッチするものが複数ある場合は `fzf` で選択できるように変更してください。
1. `fzf` はあいまい検索を行うのにとても便利で、シェルの履歴はまさにそうした検索の対象になりやすいので、`fzf` を `^R` にバインドする方法を調べてください。情報は[こちら](https://github.com/junegunn/fzf/wiki/Configuring-shell-key-bindings)にあります
1. `ack` の `--bar` オプションは何をするでしょうか?
