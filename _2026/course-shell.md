# モチベーション

コンピュータ科学者である私たちは、コンピュータが反復的な作業の手助けを得意としていることを知っています。しかし、それがプログラムに実行させたい計算だけでなく、私たち自身のコンピュータの「使い方」にも同じように当てはまることを、あまりにも頻繁に忘れてしまいます。コンピュータに関わるあらゆる問題に取り組むとき、生産性を高め、より複雑な問題を解決できるようにしてくれる膨大なツール群が、私たちの手の届くところにあります。それにもかかわらず、多くの人はそのツールのほんの一部しか活用していません。なんとかやり過ごせる程度の魔法の呪文を丸暗記しているだけで、行き詰まるとインターネットからコマンドを盲目的にコピペしてしまうのです。

この授業は[この問題に取り組む](/about/)試みです。

私たちは、すでに知っているツールを最大限に活用する方法を教え、ツールボックスに加えるべき新しいツールを紹介し、そして願わくは、自分自身でさらに多くのツールを探求する(そしておそらくは作る)ことへのワクワク感を植え付けたいと思っています。これこそが、ほとんどのコンピュータサイエンスのカリキュラムから欠けている学期(missing semester)だと私たちは考えています。

## シェルとは何か?

最近のコンピュータには、命令を与えるためのさまざまなインターフェースがあります。華やかなグラフィカルユーザーインターフェース、音声インターフェース、AR/VR、そして最近ではLLMもそうです。これらはユースケースの80%には最適ですが、できることが根本的に制限されていることがよくあります。存在しないボタンを押すことはできませんし、プログラムされていない音声コマンドを与えることもできません。コンピュータが提供するツールを最大限に活用するには、昔ながらの方法に立ち返り、テキストベースのインターフェースまで降りていく必要があります。それがシェルです。

手に入るほぼすべてのプラットフォームには、何らかの形でシェルが搭載されており、その多くでは複数のシェルから選ぶことができます。細部は異なるかもしれませんが、その核心はどれもほぼ同じです。プログラムを実行し、入力を与え、その出力を半構造化された形で調べられるようにしてくれるのです。

シェルの _プロンプト_(コマンドを入力する場所)を開くには、まず _ターミナル_ が必要です。ターミナルはシェルへの視覚的なインターフェースです。お使いのデバイスにはおそらく最初からインストールされているか、簡単にインストールできます。

- **Linux:** `Ctrl + Alt + T` を押します(ほとんどのディストリビューションで動作します)。または、アプリケーションメニューで「Terminal」を検索してください。
- **Windows:** `Win + R` を押し、`cmd` または `powershell` と入力してEnterを押します。あるいは、スタートメニューで「Terminal」または「Command Prompt」を検索してください。
- **macOS:** `Cmd + Space` を押してSpotlightを開き、「Terminal」と入力してEnterを押します。または、アプリケーション → ユーティリティ → ターミナル から見つけられます。

LinuxとmacOSでは、通常Bourne Again SHell、略して「bash」が開きます。これは最も広く使われているシェルのひとつで、その構文は他の多くのシェルで見かけるものとよく似ています。Windowsでは、実行したコマンドに応じて「batch」または「powershell」シェルが迎えてくれます。これらはWindows固有のもので、この授業で扱う対象ではありません(私たちが教える内容の大半に相当する機能はありますが)。代わりに[Windows Subsystem for Linux](https://docs.microsoft.com/en-us/windows/wsl/)かLinuxの仮想マシンを使うとよいでしょう。

他にもシェルは存在し、bashよりも使い勝手が大きく改善されていることがよくあります(fishとzshが最も一般的です)。これらは非常に人気がありますが(講師陣は全員どちらかを使っています)、bashほどどこにでもあるわけではなく、また多くの概念をbashと共有しているため、この講義では扱いません。

## なぜ気にかけるべきなのか?

シェルは(たいてい)「あちこちクリックする」よりずっと速いだけでなく、どんな単一のグラフィカルなプログラムにも簡単には見つからない表現力を備えています。これから見ていくように、シェルはプログラムを創造的な方法で _組み合わせて_、ほぼあらゆる作業を自動化する能力を与えてくれます。

シェルを使いこなせることは、オープンソースソフトウェアの世界を渡り歩くうえでも(インストール手順にシェルが必要なことがよくあります)、ソフトウェアプロジェクトの継続的インテグレーションを構築するうえでも([コード品質の講義](/2026/code-quality/)で説明します)、他のプログラムが失敗したときにエラーをデバッグするうえでも、非常に役立ちます。

## シェルの中を移動する

ターミナルを起動すると、多くの場合こんな感じの _プロンプト_ が表示されます。

```console
missing:~$
```

これがシェルへの主要なテキストインターフェースです。これは、あなたが `missing` というマシン上にいること、そして「カレントワーキングディレクトリ」、つまり現在いる場所が `~`(「ホーム」の略)であることを示しています。`$` は、あなたがrootユーザーではないことを示しています(これについては後で詳しく説明します)。このプロンプトで _コマンド_ を入力すると、それがシェルによって解釈されます。最も基本的なコマンドは、プログラムを実行することです。

```console
missing:~$ date
Fri 10 Jan 2020 11:49:31 AM EST
missing:~$
```

ここでは `date` プログラムを実行しました。これは(おそらく驚くことではありませんが)現在の日付と時刻を表示します。その後、シェルは次に実行するコマンドを尋ねてきます。コマンドは _引数_ とともに実行することもできます。

```console
missing:~$ echo hello
hello
```

この場合、シェルに `echo` プログラムを引数 `hello` とともに実行するよう指示しました。`echo` プログラムは単に自分の引数を表示します。シェルはコマンドを空白で区切って解析し、最初の単語が示すプログラムを実行して、続く各単語をそのプログラムがアクセスできる引数として渡します。空白やその他の特殊文字を含む引数(たとえば "My Photos" という名前のディレクトリ)を渡したい場合は、引数を `'` または `"` でクォートする(`"My Photos"`)か、該当する文字だけを `\` でエスケープします(`My\ Photos`)。

使い始めたばかりの頃に最も重要なコマンドは、おそらく `man` でしょう。これは「manual(マニュアル)」の略です。`man` プログラムにはいくつかの用途がありますが、そのひとつとして、システム上の任意のコマンドについて詳しい情報を調べることができます。たとえば `man date` を実行すると、`date` が何であるか、そして挙動を変えるために渡せるさまざまな引数のすべてを説明してくれます。また、ほとんどのコマンドでは `--help` を引数として渡すと、短いヘルプを表示できるのが普通です。

> `man` に加えて [`tldr`](https://tldr.sh/) をインストールして使うことを検討してみてください。よくある使用例をその場でターミナルに表示してくれます。また、LLMもたいてい、コマンドがどう動くのか、やりたいことを実現するにはどう呼び出せばよいのかを説明するのがとても得意です。

`man` の次に学ぶべき最も重要なコマンドは `cd`、すなわち「change directory(ディレクトリ変更)」です。このコマンドは実際にはシェルに組み込まれており、独立したプログラムではありません(つまり、`which cd` は「no cd found」と言うでしょう)。パスを渡すと、そのパスがカレントワーキングディレクトリになります。ワーキングディレクトリはシェルのプロンプトにも反映されます。

```console
missing:~$ cd /bin
missing:/bin$ cd /
missing:/$ cd ~
missing:~$
```

> シェルには自動補完機能が備わっているので、`<TAB>` を押せばパスをより素早く補完できることが多いです!

多くのコマンドは、他に何も指定されなければカレントワーキングディレクトリを対象に動作します。今どこにいるのか分からなくなったら、`pwd` を実行するか、環境変数 `$PWD` を表示すれば(`echo $PWD`)、どちらもカレントワーキングディレクトリを出力してくれます。

カレントワーキングディレクトリは、_相対_ パスを使えるようにしてくれるという点でも便利です。ここまで見てきたパスはすべて _絶対_ パスでした --- `/` で始まり、ファイルシステムのルート(`/`)から目的の場所までたどるのに必要なディレクトリを完全な形で示します。実際には、相対パスを使うことのほうが多いでしょう。相対パスと呼ばれるのは、カレントワーキングディレクトリからの相対で解釈されるからです。相対パス(`/` で _始まらない_ もの)では、最初のパス要素がカレントワーキングディレクトリの中で探され、続く要素は通常どおりたどられます。たとえば:

```console
missing:~$ cd /
missing:/$ cd bin
missing:/bin$
```

また、すべてのディレクトリに存在する2つの「特別な」要素があります。`.` と `..` です。`.` は「このディレクトリ」、`..` は「親ディレクトリ」を意味します。つまり:

```console
missing:~$ cd /
missing:/$ cd bin/../bin/../bin/././../bin/..
missing:/$
```

どんなコマンドの引数でも、絶対パスと相対パスはたいてい入れ替えて使えます。ただし、相対パスを使うときは、自分のカレントワーキングディレクトリがどこなのかを意識しておきましょう!

> [`zoxide`](https://github.com/ajeetdsouza/zoxide) をインストールして使うことを検討してみてください。`cd` の操作が速くなります --- `z` はよく訪れるパスを覚えてくれて、少ないタイプ量でアクセスできるようにしてくれます。

## シェルでは何が使えるのか?

しかし、シェルはどうやって `date` や `echo` のようなプログラムの場所を知るのでしょうか? シェルはコマンドの実行を求められると、`$PATH` という _環境変数_ を参照します。これは、コマンドが与えられたときにシェルがプログラムを探すべきディレクトリの一覧です。

```console
missing:~$ echo $PATH
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
missing:~$ which echo
/bin/echo
missing:~$ /bin/echo $PATH
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

`echo` コマンドを実行すると、シェルは `echo` というプログラムを実行すべきだと判断し、`$PATH` に列挙された `:` 区切りのディレクトリ一覧の中から、その名前のファイルを探します。見つかると、それを実行します(そのファイルが _実行可能_ であればですが。これについては後述します)。あるプログラム名に対してどのファイルが実行されるのかは、`which` プログラムで調べられます。また、実行したいファイルへの _パス_ を直接指定することで、`$PATH` を完全に迂回することもできます。

これは、シェルで実行できる _すべての_ プログラムを知る方法の手がかりにもなります。`$PATH` 上のすべてのディレクトリの中身を一覧すればよいのです。これは、ファイルを一覧表示する `ls` プログラムにディレクトリのパスを渡すことで実現できます。

```console
missing:~$ ls /bin
```

> より人に優しい `ls` として、[`eza`](https://eza.rocks/) をインストールして使うことを検討してみてください。

これを実行すると、ほとんどのコンピュータでは _大量の_ プログラムが表示されますが、ここでは特に重要なものだけに絞って見ていきます。まずは簡単なものから:

- `cat file` は、`file` の内容を表示します。
- `sort file` は、`file` の各行をソートした順序で表示します。
- `uniq file` は、`file` から連続した重複行を取り除きます。
- `head file` と `tail file` は、それぞれ `file` の最初と最後の数行を表示します。

> シンタックスハイライトとスクロールのために、`cat` の代わりに[`bat`](https://github.com/sharkdp/bat) をインストールして使うことを検討してみてください。

また、`grep pattern file` というコマンドもあります。これは `file` の中から `pattern` にマッチする行を見つけます。これは _非常に_ 便利で、思った以上に幅広い機能を備えているので、もう少し詳しく見ておく価値があります。`pattern` は実際には _正規表現_ で、非常に複雑なパターンを表現できます --- 正規表現についてはコード品質の講義で[扱います](/2026/code-quality/#regular-expressions)。ファイルの代わりにディレクトリを指定する(または省略して `.` にする)こともでき、`-r` を渡すとディレクトリ内のすべてのファイルを再帰的に検索します。

> `grep` の代わりに[`ripgrep`](https://github.com/BurntSushi/ripgrep) をインストールして使うことを検討してみてください。より高速で人に優しい(ただし移植性は低い)代替品です。`ripgrep` はデフォルトでカレントワーキングディレクトリを再帰的に検索してくれます!

もう少し複雑なインターフェースを持つ、とても便利なツールもあります。その筆頭が `sed` で、これはプログラムから操作できるファイルエディタです。ファイルを自動編集するための独自のプログラミング言語を持っていますが、最もよくある使い方はこうです。

```console
missing:~$ sed -i 's/pattern/replacement/g' file
```

これは `file` 内のすべての `pattern` を `replacement` に置換します。`-i` は、置換をインラインで(つまり、`file` を変更せずに置換後の内容を表示するのではなく、ファイル自体を書き換えて)行いたいことを示します。`s/` は、sedのプログラミング言語で置換を行いたいことを表す書き方です。`/` はパターンと置換文字列を区切ります。そして末尾の `/g` は、各行で最初の1つだけでなく _すべての_ 出現を置換したいことを示します。`grep` と同様に、ここでの `pattern` は正規表現なので、大きな表現力が得られます。正規表現による置換では、`replacement` からマッチしたパターンの一部を参照することもできます。その例はすぐ後で見ます。

次は `find` です。これは、特定の条件にマッチするファイルを(再帰的に)探せるコマンドです。たとえば:

```console
missing:~$ find ~/Downloads -type f -name "*.zip" -mtime +30
```

これは、ダウンロードディレクトリの中から30日より古いZIPファイルを見つけます。

```console
missing:~$ find ~ -type f -size +100M -exec ls -lh {} \;
```

これは、ホームディレクトリの中から100Mより大きいファイルを見つけて一覧表示します。`-exec` は、単独の `;` で終端された _コマンド_ を受け取ることに注意してください(この `;` は空白と同じようにエスケープする必要があります)。`{}` の部分は、`find` によってマッチした各ファイルのパスに置き換えられます。

```console
missing:~$ find . -name "*.py" -exec grep -l "TODO" {} \;
```

これは、TODO項目を含む `.py` ファイルを見つけます。

`find` の構文は少し取っつきにくいかもしれませんが、どれほど便利になり得るか、感覚をつかんでもらえたら幸いです!

> `find` の代わりに [`fd`](https://github.com/sharkdp/fd) をインストールして使うことを検討してみてください。より人に優しい(ただし移植性は低い!)体験が得られます。

次の議題は `awk` です。`sed` と同じく、独自のプログラミング言語を持っています。`sed` がファイルの編集のために作られているのに対して、`awk` はファイルの解析のために作られています。`awk` の圧倒的に多い使い方は、規則的な構文を持つデータファイル(CSVファイルなど)から、各レコード(つまり行)の特定の部分だけを抽出することです。

```console
missing:~$ awk '{print $2}' file
```

これは、`file` の各行について、空白で区切られた2番目の列を表示します。`-F,` を加えると、各行のカンマで区切られた2番目の列を表示します。`awk` はもっと多くのことができます --- 行のフィルタリング、集計の計算など --- その一端は演習で味わってください。

これらのツールを組み合わせると、こんな凝ったこともできます。

```console
missing:~$ ssh myserver 'journalctl -u sshd -b-1 | grep "Disconnected from"' \
  | sed -E 's/.*Disconnected from .* user (.*) [^ ]+ port.*/\1/' \
  | sort | uniq -c \
  | sort -nk1,1 | tail -n10 \
  | awk '{print $2}' | paste -sd,
postgres,mysql,oracle,dell,ubuntu,inspur,test,admin,user,root
```

これは、リモートサーバーからSSHのログを取得し(`ssh` については次の講義で詳しく説明します)、切断メッセージを検索し、それぞれのメッセージからユーザー名を抽出して、上位10個のユーザー名をカンマ区切りで表示します。すべてが1つのコマンドで! 各ステップの分解は演習として残しておきます。

## シェルの言語 (bash)

先ほどの例では、新しい概念が登場しました。パイプ(`|`)です。これは、あるプログラムの出力を別のプログラムの入力へとつなげてくれます。これが機能するのは、ほとんどのコマンドラインプログラムが、`file` 引数が与えられなければ「標準入力」(普段キー入力が届く場所)を対象に動作するからです。`|` は、`|` の前のプログラムの「標準出力」(普段ターミナルに表示されるもの)を受け取り、それを `|` の後のプログラムの標準入力にします。これによってシェルのプログラムを _合成_ できるようになり、シェルがこれほど生産的な作業環境である理由の一端となっています!

実際、ほとんどのシェルは、PythonやRubyと同じように、完全なプログラミング言語(bashなど)を実装しています。変数、条件分岐、ループ、関数があります。シェルでコマンドを実行するとき、あなたは実はシェルが解釈する小さなコードを書いているのです。今日はbashのすべてを教えることはしませんが、特に役立つであろう部分をいくつか紹介します。

まず、リダイレクトです。`>file` を使うと、プログラムの標準出力をターミナルではなく `file` に書き込めます。後から分析するのが楽になります。`>>file` は `file` を上書きするのではなく追記します。また `<file` は、プログラムの標準入力として、キーボードではなく `file` から読み込むようシェルに指示します。

> ここで `tee` プログラムに触れておきましょう。`tee` は標準入力を標準出力に表示します(まるで `cat` のように!)が、同時にそれをファイルにも書き込みます。つまり `verbose cmd | tee verbose.log | grep CRITICAL` とすれば、詳細なログ全体をファイルに残しつつ、ターミナルをすっきり保てます!

次に、条件分岐です。`if command1; then command2; command3; fi` は `command1` を実行し、それがエラーにならなければ `command2` と `command3` を実行します。必要なら `else` 節を付けることもできます。`command1` として最もよく使われるのは `test` コマンドで、しばしば単に `[` と略記されます。これを使うと、「ファイルが存在するか」(`test -f file` / `[ -f file ]`)や「文字列が別の文字列と等しいか」(`[ "$var" = "string" ]`)といった条件を評価できます。bashには `[[ ]]` もあります。これは `test` の「より安全な」組み込み版で、クォート周りの奇妙な挙動が少なくなっています。

bashには2種類のループ、`while` と `for` もあります。`while command1; do command2; command3; done` は、先ほどの `if` コマンドと同じように機能しますが、`command1` がエラーにならない限り、全体を何度も繰り返し実行する点が異なります。`for varname in a b c d; do command; done` は `command` を4回実行し、そのたびに `$varname` に `a`、`b`、`c`、`d` のいずれかが設定されます。項目を明示的に列挙する代わりに、「コマンド置換」を使うこともよくあります。たとえば:

```bash
for i in $(seq 1 10); do
```

これは `seq 1 10` というコマンド(1から10までの数を両端含めて表示します)を実行し、`$()` 全体をそのコマンドの出力で置き換えることで、10回繰り返すforループになります。古いコードでは `$()` の代わりにバッククォート(``for i in `seq 1 10`; do`` のような形)を見かけることもありますが、`$()` の形はネストできるので、そちらを強く推奨します。

長いシェルスクリプトをプロンプトに直接書くことも _できます_ が、普通は `.sh` ファイルに書きたくなるでしょう。たとえば、次のスクリプトは、バックグラウンドでCPUに負荷をかけながら、プログラムが失敗するまでループで実行し続け、失敗した実行の出力だけを表示します(たとえば不安定なテスト(flaky test)を再現するのに便利です)。

```bash
#!/bin/bash
set -euo pipefail

# Start CPU stress in background
stress --cpu 8 &
STRESS_PID=$!

# Setup log file
LOGFILE="test_runs_$(date +%s).log"
echo "Logging to $LOGFILE"

# Run tests until one fails
RUN=1
while cargo test my_test > "$LOGFILE" 2>&1; do
    echo "Run $RUN passed"
    ((RUN++))
done

# Cleanup and report
kill $STRESS_PID
echo "Test failed on run $RUN"
echo "Last 20 lines of output:"
tail -n 20 "$LOGFILE"
echo "Full log: $LOGFILE"
```

この中には新しい要素がいくつも登場しているので、時間をかけて掘り下げてみることをおすすめします。プログラムを並行に実行するためのバックグラウンドジョブ(`&`)、少し込み入った[シェルのリダイレクト](https://www.gnu.org/software/bash/manual/html_node/Redirections.html)、そして[算術展開](https://www.gnu.org/software/bash/manual/html_node/Arithmetic-Expansion.html)など、便利なシェルの使い方を組み立てるうえでとても役立ちます。

ただ、このプログラムの最初の2行については少し時間を割いておく価値があります。1行目は「シェバン(shebang)」です --- シェルスクリプト以外のファイルの先頭でも見かけることがあるでしょう。`#!/path` という魔法の呪文で始まるファイルが実行されると、シェルは `/path` にあるプログラムを起動し、そのファイルの内容を入力として渡します。シェルスクリプトの場合、これはスクリプトの内容を `/bin/bash` に渡すことを意味しますが、シェバン行を `/usr/bin/python` にしてPythonスクリプトを書くこともできます!

2行目はbashを「より厳格」にして、シェルスクリプトを書くときの落とし穴の数々を軽減するための方法です。`set` は実にさまざまな引数を取れますが、手短に言うと: `-e` は、いずれかのコマンドが失敗したらスクリプトを早期終了させます。`-u` は、未定義の変数を使ったときに、単に空文字列として扱うのではなくスクリプトをクラッシュさせます。そして `-o pipefail` は、`|` の連なりの中のプログラムが失敗したら、シェルスクリプト全体も早期終了するようにします。

> シェルプログラミングは、他のプログラミング言語と同じく奥深いトピックですが、注意してください。bashには異常なほど多くの落とし穴があり、それを[列挙する](https://mywiki.wooledge.org/BashPitfalls)ことに特化したウェブサイトが[複数](https://tldp.org/LDP/abs/html/gotchas.html)存在するほどです。シェルスクリプトを書くときは[shellcheck](https://www.shellcheck.net/)を大いに活用することを強くおすすめします。また、LLMもシェルスクリプトの作成やデバッグ、さらにはbashでは手に負えないほど大きくなった(100行超の)スクリプトを「本物の」プログラミング言語(Pythonなど)に翻訳するのが得意です。

# 次のステップ

ここまでで、基本的な作業をこなせる程度にはシェルを使いこなせるようになりました。目的のファイルを探して移動したり、ほとんどのプログラムの基本機能を使ったりできるはずです。次の講義では、シェルと、世の中にある数多くの便利なコマンドラインプログラムを使って、より複雑な作業を実行・自動化する方法について話します。

# 演習

このコースのすべての授業には、一連の演習が付いています。具体的な課題を与えるものもあれば、「XとYのプログラムを使ってみよう」のような自由回答式のものもあります。ぜひ試してみることを強くおすすめします。

演習の解答は用意していません。特定の箇所で行き詰まったら、[Discord](https://ossu.dev/#community)の `#missing-semester-forum` に投稿するか、これまでに試したことを書いたメールを私たちに送ってください。できる限りお手伝いします。これらの演習は、LLMとの会話の最初のプロンプトとしてもうまく機能するでしょう。対話しながらトピックを深掘りできます。これらの演習の本当の価値は、答えそのものではなく、答えを発見するまでの道のりにあります。最短経路で解答を探すのではなく、寄り道をしながら「なぜ?」と問い続けることをおすすめします。

1. このコースでは、BashやZSHのようなUnixシェルを使う必要があります。LinuxまたはmacOSを使っているなら、特別なことをする必要はありません。Windowsを使っている場合は、cmd.exeやPowerShellを実行していないことを確認する必要があります。Unixスタイルのコマンドラインツールを使うには、[Windows Subsystem for Linux](https://docs.microsoft.com/en-us/windows/wsl/)かLinuxの仮想マシンが使えます。適切なシェルを実行していることを確認するには、`echo $SHELL` コマンドを試してください。`/bin/bash` や `/usr/bin/zsh` のような表示が出れば、正しいプログラムを実行できています。

1. `ls` の `-l` フラグは何をするものでしょうか? `ls -l /` を実行して出力を調べてください。各行の最初の10文字は何を意味しているでしょうか? (ヒント: `man ls`)

1. `find ~/Downloads -type f -name "*.zip" -mtime +30` というコマンドの `*.zip` は「グロブ(glob)」です。グロブとは何でしょうか? テスト用のディレクトリをいくつかのファイルと一緒に作り、`ls *.txt`、`ls file?.txt`、`ls {a,b,c}.txt` のようなパターンを試してください。Bashマニュアルの[Pattern Matching](https://www.gnu.org/software/bash/manual/html_node/Pattern-Matching.html)を参照してください。

1. `'single quotes'`、`"double quotes"`、`$'ANSI quotes'` の違いは何でしょうか? リテラルの `$`、`!`、改行文字を含む文字列をechoするコマンドを書いてください。[Quoting](https://www.gnu.org/software/bash/manual/html_node/Quoting.html)を参照してください。

1. シェルには3つの標準ストリームがあります。stdin (0)、stdout (1)、stderr (2) です。`ls /nonexistent /tmp` を実行し、stdoutをあるファイルへ、stderrを別のファイルへリダイレクトしてください。両方を同じファイルにリダイレクトするにはどうすればよいでしょうか? [Redirections](https://www.gnu.org/software/bash/manual/html_node/Redirections.html)を参照してください。

1. `$?` は直前のコマンドの終了ステータスを保持します(0 = 成功)。`&&` は直前のコマンドが成功した場合にのみ次のコマンドを実行し、`||` は失敗した場合にのみ実行します。`/tmp/mydir` がまだ存在しない場合にのみ作成するワンライナーを書いてください。[Exit Status](https://www.gnu.org/software/bash/manual/html_node/Exit-Status.html)を参照してください。

1. なぜ `cd` は独立したプログラムではなく、シェル自体に組み込まれていなければならないのでしょうか? (ヒント: 子プロセスが親プロセスに対して影響を与えられるもの・与えられないものについて考えてみてください。)

1. ファイル名を引数(`$1`)として受け取り、そのファイルが存在するかどうかを `test -f` または `[ -f ... ]` で確認するスクリプトを書いてください。ファイルが存在するかどうかに応じて異なるメッセージを表示するようにしましょう。[Bash Conditional Expressions](https://www.gnu.org/software/bash/manual/html_node/Bash-Conditional-Expressions.html)を参照してください。

1. 前の演習のスクリプトをファイル(例: `check.sh`)に保存してください。`./check.sh somefile` で実行してみましょう。何が起こるでしょうか? 次に `chmod +x check.sh` を実行してからもう一度試してください。なぜこのステップが必要なのでしょうか? (ヒント: `chmod` の前後で `ls -l check.sh` の出力を見比べてみてください。)

1. スクリプトの `set` フラグに `-x` を追加すると何が起こるでしょうか?簡単なスクリプトで試して、出力を観察してください。[The Set Builtin](https://www.gnu.org/software/bash/manual/html_node/The-Set-Builtin.html)を参照してください。

1. ファイルを、今日の日付をファイル名に含むバックアップとしてコピーするコマンドを書いてください(例: `notes.txt` → `notes_2026-01-12.txt`)。(ヒント: `$(date +%Y-%m-%d)`)。[Command Substitution](https://www.gnu.org/software/bash/manual/html_node/Command-Substitution.html)を参照してください。

1. 講義に出てきた不安定なテスト用のスクリプトを、`cargo test my_test` をハードコードする代わりに、テストコマンドを引数として受け取るように変更してください。(ヒント: `$1` または `$@`)。[Special Parameters](https://www.gnu.org/software/bash/manual/html_node/Special-Parameters.html)を参照してください。

1. パイプを使って、ホームディレクトリ内で最もよく使われているファイル拡張子の上位5つを見つけてください。(ヒント: `find` と、`grep`・`sed`・`awk` のいずれか、`sort`、`uniq -c`、`head` を組み合わせます。)

1. `xargs` はstdinから読み込んだ行をコマンドの引数に変換します。`find` と `xargs` を組み合わせて(`find -exec` は使わずに)、あるディレクトリ内のすべての `.sh` ファイルを見つけ、それぞれの行数を `wc -l` で数えてください。ボーナス: 空白を含むファイル名にも対応させてください。(ヒント: `-print0` と `-0`)。`man xargs` を参照してください。

1. `curl` を使ってこのコースのウェブサイト(`https://missing.csail.mit.edu/`)のHTMLを取得し、`grep` にパイプして、いくつの講義が掲載されているか数えてください。(ヒント: 講義ごとに1回出現するパターンを探しましょう。進捗表示を消すには `curl -s` を使います。)

1. [`jq`](https://jqlang.github.io/jq/) はJSONデータを処理するための強力なツールです。`curl` で `https://microsoftedge.github.io/Demos/json-dummy-data/64KB.json` にあるサンプルデータを取得し、`jq` を使ってversionが6より大きい人の名前だけを抽出してください。(ヒント: まず `jq .` にパイプして構造を確認してから、`jq '.[] | select(...) | .name'` を試してみましょう)

1. `awk` は列の値に基づいて行をフィルタリングしたり、出力を加工したりできます。たとえば `awk '$3 ~ /pattern/ {$4=""; print}'` は、3列目が `pattern` にマッチする行だけを、4列目を省いて表示します。2列目が100より大きい行だけを表示し、1列目と3列目を入れ替える `awk` コマンドを書いてください。次のコマンドでテストできます: `printf 'a 50 x\nb 150 y\nc 200 z\n'`

1. 講義に出てきたSSHログのパイプラインを分解してみましょう。各ステップは何をしているでしょうか? その後、似たようなものを作って、`~/.bash_history`(または `~/.zsh_history`)から自分が最もよく使うシェルコマンドを見つけてください。
